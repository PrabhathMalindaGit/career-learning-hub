# AI Learning Assistant Legacy Feature Inventory

## 1. Executive Summary

The legacy AI Learning Assistant contains useful product workflows for private
PDF study, document chat, flashcards, and quizzes. Its implementation is not
compatible with the active platform's authentication, asset, job, validation,
ownership, and answer-key boundaries.

No legacy feature qualifies for `PORT`. The inspection identified 42 meaningful
behaviors or technical responsibilities: 21 `REBUILD`, 9 `REFERENCE ONLY`, and
12 `REJECT`. The active Career Learning Hub backend already implements most of
the required capabilities. Phase 12 is primarily a frontend integration phase,
subject to the original-PDF viewing decision recorded in the migration plan.

## 3. Inspection Method

1. Verified the active repository, clean Phase 10 baseline, branch, commit, and
   governance state.
2. Captured a deterministic legacy metadata baseline with generated,
   dependency, cache, and temporary paths excluded.
3. Listed relevant legacy source, then inspected manifests, routes,
   controllers, models, services, state, pages, and learning components.
4. Compared those findings with the active Learning routes, controllers,
   services, models, asset policy, jobs, frontend scaffold, and Phase 6
   documentation.
5. Performed a focused static risk review. No runtime claims are made.

## 4. Legacy Architecture

| Boundary | Evidence-backed finding |
|---|---|
| Frontend | React 19 and Vite, JavaScript JSX, React Router, Axios, Tailwind CSS, local component state. See `frontend/ai-learning-assistant/package.json` and `src/App.jsx`. |
| Backend | Express 5 JavaScript API with route/controller/model separation. See `backend/server.js`. |
| Database | MongoDB through Mongoose. Documents, chat histories, flashcard sets, quizzes, and users are separate models, but messages, cards, questions, and answers are embedded arrays. |
| Authentication | Seven-day JWT bearer token generated by `backend/controllers/authController.js:generateToken`; persisted by `frontend/ai-learning-assistant/src/context/AuthContext.jsx:login`. |
| API boundary | Hard-coded `http://localhost:8000`; Axios interceptor reads the bearer token from `localStorage`. |
| Provider | Server-side `@google/genai` calls in `backend/utils/geminiService.js`, coupled to `gemini-2.5-flash-lite`. |
| Document processing | Multer disk upload, in-process fire-and-forget PDF parsing, whole-document extraction, word chunking, and MongoDB update. |
| Storage | Local disk under `backend/uploads/documents`; all uploads are exposed through `/uploads`. |
| Persistent client state | JWT and user record in `localStorage`; feature data otherwise uses component memory and API reads. |
| Job model | No durable job record or worker. `uploadDocument` calls `processPDF(...).catch(...)` after returning. AI generation blocks the request. |
| Main entities | `User`, `Document`, `ChatHistory`, `Flashcard`, and `Quiz`. |

## 7. Document Upload and Processing Findings

- The legacy upload path has a useful title/file workflow but only checks the
  declared MIME type and size. It does not verify PDF magic bytes.
- The stored filename includes the original filename and the stored `filePath`
  is an HTTP URL. This conflicts with the active private asset model.
- Processing is not durable. A process restart after the `201` response can
  leave a document in `processing`.
- The active backend already performs memory upload, private asset validation,
  quota enforcement, owned asset reads, page limits, durable job processing,
  structured summary validation, and explicit non-OCR errors.

## 8. Document Viewing and Page-Awareness Findings

- Legacy detail embeds a publicly served PDF and returns the full extracted
  text and chunks on one response.
- Legacy chunk pages are always `0`, even though the document model names the
  field `pageNumber`. No source page shown from this data would be factual.
- Active chunks preserve one-based `pageStart/pageEnd` and are paginated.
- Active learning detail does not expose `assetId` or an authenticated download
  target. The operator approved the smallest bounded backend/shared-contract
  extension for an owner-authorized, short-lived target. It must not expose
  storage internals, persist in the browser, or replace chunk grounding.

## 9. Chat and Grounding Findings

- Legacy chat scopes document reads by the authenticated user, retrieves at
  most three keyword-ranked chunks, and tells the provider to admit missing
  evidence.
- It stores only chunk indexes, shows no source pages, sends raw provider text
  to Markdown rendering, and embeds all messages in one growing record.
- Active chat binds document, conversation, message, user, and job identities;
  uses bounded history/retrieval; treats all content as untrusted; validates
  structured output; verifies cited chunks; and stores factual source pages.

## 10. Flashcard Findings

- The legacy flip, next/previous, set selection, and empty-state flow are useful
  interaction references.
- Generation count has no enforced upper bound at the controller/provider
  boundary, output is delimiter parsed, and generated cards have no factual
  source references.
- Active generation enforces exact bounded count, contiguous indexes,
  duplicate-front rejection, structured output, idempotency, and verified
  source pages.
- Persisted review counts, stars, and standalone set deletion have no active
  backend contracts. They are not Phase 12 commitments.

## 11. Quiz and Answer-Key Findings

- `getQuizById` and document quiz listing serialize the full `Quiz`, including
  every `correctAnswer` and `explanation`, before submission.
- `generateQuiz` also returns the newly created full quiz record, including
  keys.
- Legacy scoring runs on the server, but accepts partial answer arrays, ignores
  out-of-range question indexes, stores only one mutable result, and has no
  attempt history.
- Active quiz taking explicitly selects only prompt, choices, and source pages.
  Correct choice and explanation appear only after a successful owned
  submission or owned completed-attempt read.

## 12. Authentication and Ownership Findings

- Legacy controllers generally derive `userId` from `req.user` and include it
  in document, flashcard, quiz, and chat queries.
- The auth system is incompatible with the active platform because it issues a
  long-lived bearer token and stores it in `localStorage`.
- Active middleware binds nested resources to authenticated ownership and uses
  the same safe 404 for missing and foreign IDs.

## 13. AI Provider and Prompt Findings

- Provider calls occur on the legacy server, not in the browser. No hard-coded
  API key was found in inspected source.
- The provider and model are hard-coded, a missing key exits the server, and
  request paths call Gemini directly.
- Flashcard and quiz output use delimiter parsing. Summary, chat, and
  explanation accept raw text without a structured allowlist.
- Active AI services isolate provider selection behind the gateway, validate
  Zod schemas, bind jobs and users, bound context, treat document/user text as
  untrusted, and verify cited chunks.

## 14. Storage and Deletion Findings

- `/uploads` is public, so anyone with a URL can fetch a document without an
  ownership check.
- `deleteDocument` passes the stored HTTP URL to `fs.unlink`, ignores failure,
  deletes only the document record, and leaves dependent chat, flashcard, and
  quiz data.
- Active deletion first removes the private storage object, then uses a MongoDB
  transaction to delete messages, conversations, flashcards, sets, attempts,
  questions, quizzes, chunks, and the document. The job is owned and
  idempotent.

## 15. UX and Responsive Findings

- Useful references: document-card library, tabbed document workspace,
  focused loading/empty states, destructive confirmations, flashcard reveal,
  quiz progress/navigation, and mobile sidebar.
- Weak points: icon-only controls without reliable accessible names, hover-only
  delete visibility, click-only card flipping, no request cancellation, limited
  inline recovery, no stale-route protection, and provider Markdown links.
- Phase 12 must use the active shell and styles, support 320px layouts,
  keyboard/focus behavior, reduced motion, and factual state labels.
